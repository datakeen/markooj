# Translating Markooj

Markooj's menus, buttons and messages can be shown in eleven languages. This page is the contract for two groups of people:

- **Developers** who write interface text in the code (how to wrap it, what never to wrap).
- **Translators and reviewers** who write and check the translations (file layout, rules, the check script).

The document a person writes is never translated or changed by any of this. Its language, direction and fonts follow its own
settings (`lang:` and `dir:` in the front matter, and per-paragraph direction).

## Languages

| Code | Language | Native name | Direction | Interface font |
| --- | --- | --- | --- | --- |
| `en` | English (source) | English | left to right | system |
| `zh-CN` | Chinese (Simplified) | 简体中文 | left to right | Microsoft YaHei UI / PingFang SC / Noto Sans CJK SC |
| `ur` | Urdu | اردو | right to left | Noto Naskh Arabic; Noto Nastaliq Urdu for large headings |
| `ur-Latn` | Roman Urdu | Roman Urdu | left to right | system |
| `pnb` | Punjabi (Shahmukhi) | پنجابی | right to left | as Urdu |
| `ja` | Japanese | 日本語 | left to right | Yu Gothic UI / Hiragino Sans / Noto Sans CJK JP |
| `ar` | Arabic | العربية | right to left | system font, Noto Naskh Arabic after it |
| `sv` | Swedish | Svenska | left to right | system |
| `es` | Spanish | Español | left to right | system |
| `fr` | French | Français | left to right | system |
| `pt-BR` | Portuguese (Brazil) | Português (Brasil) | left to right | system |

`qps` is a test language (see "Pseudo-locale") and is not offered to users.

**Why Naskh for Urdu and Punjabi menus.** At the same font size, Nastaliq words reach much higher and lower than Naskh words
(the smoke test checks that the difference is more than 25 %), and their small letter bodies are hard to read below about 15 px. Ribbon buttons and the status bar are 22 px high with 11–13 px text, so Nastaliq
would be cut off or too small there. The interface therefore uses Noto Naskh Arabic for all labels and Noto Nastaliq Urdu only
for large headings (File page titles, Options section titles, the Welcome title). Both fonts come with Markooj, so menus
look the same on every computer. Documents in Urdu still use Nastaliq on the page. The smoke test
`i18n: Urdu interface fonts (screenshot)` draws both fonts side by side.

## Files

```
locales/
  languages.json             code, name, native, dir, intl (numbers, dates), plural (Intl.PluralRules locale), font, completeness
  en/shell.json              the English source, split into groups
  en/app.json
  en/editors.json
  en/language.json
  en/system.json
  <code>/shell.json …        the same groups and the same keys, translated
  <code>/GLOSSARY.md         agreed terms and style for that language (fill it first)
```

Suggested groups (which file a string goes into):

| Group | Code it comes from |
| --- | --- |
| `shell` | `src/index.html`, `src/shell.js`, `src/tooltips.js`, `src/keytips.js`, `src/word-keys.js`, `src/integration.js` |
| `app` | `src/app.js`, `src/core.js`, `src/commands.js`, health, Recover, Welcome, tours, goals, Features (`src/features.js`) |
| `editors` | the editors, tables, cross-references, research, pictures, the equation editor, `src/exporter.js`, viewers, the Help window (its pages stay English) |
| `language` | `src/lang.js`, keyboards, aarab, dates, typing aids, multi-cursor, the Writing Assistant (`src/writing/`), `src/i18n.js` |
| `system` | `main.js`, `main-*.js`, `preload.js`, Split, ruler, windows, Developer, Add-ins and the Add-in Store, the add-ins that come with Markooj (`addons/*.js`), and any other file |

A key lives in one group only. If two parts of the code use the same English text with the same meaning, they share one key.
At run time every group of a language is merged, so the group only decides who maintains the string.

## Keys and values

**The key is the exact US English text**, as the user sees it: `"Save as…": "Save as…"` in English, `"Save as…": "Enregistrer sous…"`
in French. Code stays readable (`app.t('Save as…')`), and a missing translation simply shows the English.

In `locales/en/*.json` the value is the same text as the key (without a context marker). To change English wording, change the
key in the code and in every catalog; the check script finds keys that are no longer used.

**Context marker.** When the same English word means two things, add `@@` and a few lower-case words at the very end of the key:

```js
app.t('Open@@verb')          // a button: open a file
app.t('Open@@adjective')     // a state: the document is open
app.t('Insert@@ribbon tab')  // the tab name, not the action
```

The marker is never shown: English displays `Open`. The context is lower-case letters, digits, spaces, `_` or `-`, at most 48
characters. Use it only when a translator would otherwise have to guess.

**Placeholders** are `{name}`: letters, digits and `_`. Never build a sentence by joining pieces:

```js
app.t('Saved {name}', { name: doc.title })            // right
'Saved ' + doc.title                                    // wrong: translators cannot move the name
app.t('Saved') + ' ' + doc.title                        // wrong
```

A translation may move placeholders anywhere and must keep all of them. `{#eq:x}` and other braces that are not a single word
are plain text.

**Plurals.** Text with a number uses `{count}` and an object of plural forms. The key is the English "other" form:

```json
"{count} files": { "one": "{count} file", "other": "{count} files" }
```

```js
app.tn('{count} files', n)            // the same as app.t('{count} files', { count: n })
```

Each language writes the categories its grammar needs (from `Intl.PluralRules`):

| Language | Categories |
| --- | --- |
| Arabic | zero, one, two, few, many, other |
| French, Spanish, Portuguese | one, many, other (`many` is only for millions; it may be left out) |
| English, Urdu, Roman Urdu, Punjabi, Swedish | one, other |
| Chinese, Japanese | other |

French counts 0 as "one" (`0 fichier`); English counts 0 as "other" (`0 files`). A form may leave out `{count}` ("one file"
written as a word). `{count}` is written with the language's digit grouping (12,345 / 12 345).

**HTML.** Most strings are plain text. A string may contain simple inline tags (`<b>`, `<kbd>`, `<code>`) only when it is used
with `app.th` or `data-i18n-html`; the translation must keep the same tags.

**Notes for translators.** Keys starting with `@` are not strings. `"@notes": { "Save as…": "File menu command" }` explains a
string; `"@same": ["Version", "Contact"]` lists strings that are right as in English for this language (the check stops warning).

## Using it in code (developers)

### In the window

`src/i18n-core.js` and `src/i18n.js` load first in `src/index.html`, before every other script; `core.js` adds the functions
to `app`:

| Call | Returns |
| --- | --- |
| `app.t(text, vars?)` | translated plain text |
| `app.tn(text, count, vars?)` | plural text (`vars.count` = count) |
| `app.th(text, vars?)` | like `app.t`, with the vars HTML-escaped, for `innerHTML` templates |
| `app.tm(text)` | `text` unchanged: marks English text in data tables for the check script |
| `app.i18n.language()` | the current code, for example `ur` |
| `app.i18n.setting()` | the setting `uiLanguage` (`''` = follow the system) |
| `app.i18n.setLanguage(code, {quiet}?)` | switch now (`''` = follow the system); Promise of true/false |
| `app.i18n.languages()` | `[{code, name, native, dir, intl, plural, font, completeness}]` |
| `app.i18n.info(code?)`, `nativeName(code)` | one language |
| `app.i18n.dir()`, `isRtl()` | `'rtl'` / `'ltr'` |
| `app.i18n.onChange(fn)` | `fn({language, prev, dir, rtl})`; returns a function that removes it |
| `app.i18n.apply(el)` | fills `data-i18n*` attributes inside `el` |
| `app.i18n.number(n, opts)`, `percent`, `date(d, opts)`, `time`, `dateTime`, `list(items, opts)`, `compare(a, b)`, `relative(value, unit)` | `Intl` formatting in the interface language |
| `app.i18n.plural(n)` | the plural category of n |
| `app.i18n.picker()`, `openMenu(anchor)`, `renderOptions(el)`, `welcomeStep(sheet)` | the language pickers |
| `app.i18n.scanUntranslated(root)` | visible text that did not go through `app.t` (pseudo-locale test) |

`window.mkI18n.t` / `tn` / `th` / `tm` work before `core.js` (for the rare file that needs them that early).
The event `i18n:changed` (`{language, prev, dir, rtl}`) fires on `app.events` after every switch.

**Translate when you draw, not when you register.** The language can change while Markooj runs. Text computed once at load
time stays in the old language until the next start.

```js
// right: the label is translated each time the menu is drawn
function menuItems() { return [{ label: app.t('Close tab'), run: closeTab }]; }

// wrong: translated once, when the file loads
const ITEMS = [{ label: app.t('Close tab'), run: closeTab }];
```

### Data tables (ribbon groups, commands, options, menus)

Register English, marked with `app.tm`, and let the code that draws it call `app.t`:

```js
app.commands.register('table.copyOffice', {
  label: app.tm('Copy for Word/Excel'),
  description: app.tm('Copy the table so Word and Excel paste it as a real table.'),
  run: copyOffice,
});
app.ribbon.addGroup('insert', { id: 'x', label: app.tm('Pictures'), items: [{ type: 'big', command: 'pictures.findMissing', label: app.tm('Find missing') }] });
const ALIGN = [{ value: 'left', label: app.tm('Left') }, { value: 'center', label: app.tm('Center') }];
```

Renderers (ribbon, palette, ScreenTips, status bar, Options, menus) call `app.t(label)` on whatever label they are given. A label
that is not in any catalog (a macro name, an add-in's own label) comes back unchanged, so this is always safe.

### HTML built in JavaScript

```js
el.innerHTML = `<h3>${app.th('Save changes to “{name}”?', { name: doc.title })}</h3>
  <p>${app.th('Your text is kept in File → Recover for {count} days.', { count: days })}</p>`;
b.textContent = app.t('Try again');
b.title = app.t('Close');
b.dataset.tip = app.t('Bold'); b.dataset.tipD = app.t('Make the selected text bold.');
```

Use `app.th` inside `innerHTML` (it escapes the values) and `app.t` for `textContent`, attributes and `h()` helpers.
Keep one sentence per key; a paragraph with two sentences is fine as one key when the sentences belong together.

### Static HTML (`src/index.html`)

```html
<b data-i18n="Drop to open">Drop to open</b>
<button title="Leave focus (Esc)" data-i18n-title="Leave focus (Esc)"><svg …/><span data-i18n="Leave focus">Leave focus</span></button>
<aside aria-label="Outline" data-i18n-aria-label="Outline"></aside>
```

Attributes: `data-i18n` (text), `data-i18n-html` (trusted catalog HTML), `data-i18n-title`, `-aria-label`, `-placeholder`,
`-alt`, `-tip`, `-tip-d`, `-label`, and `data-i18n-vars='{"n":3}'`. `data-i18n` replaces the element's whole text, so put it on
an element that holds only the text (wrap the text in a `<span>` next to an icon). They are filled at start and on every switch.

### Switching while Markooj runs

Switching is live and never touches documents. After `i18n:changed`, `src/i18n.js` fills the `data-i18n` attributes again,
closes the command search, redraws the ribbon, the document tabs and the status bar, and reopens the File page that was open.
**Any module that keeps other interface on screen (a pane, an open dialog, the Welcome sheet) redraws it on `i18n:changed`**:

```js
app.events.on('i18n:changed', () => { if (pane.isOpen()) pane.render(); });
```

### Main process

```js
const I18N = require('./main-i18n');          // main.js already has it as I18N
dialog.showMessageBox(win, { message: I18N.t('Close Markooj anyway?'), buttons: [I18N.t('Close anyway'), I18N.t('Cancel')] });
```

`I18N.t`, `I18N.tn`, `I18N.language()`, `I18N.dir()`, `I18N.onChange(fn)` (rebuild native menus there). Main uses the same
catalogs and always knows the window's language. Error messages that main sends to the window are translated in main with
`I18N.t` (the window shows them as they arrive). For the scanner, other files of the main process call `I18N.t(…)` too.

A file may give short names to the functions: `const t = app.t;` plus the comment `/* i18n-aliases: t, tn */` at the top so
the check script finds `t('…')` calls.

### Workers

Workers have no `app`. Send English keys (and their vars) from the worker and translate them in the window when they are shown.

### Never translate

- Markdown syntax and anything the user types into the document (`**bold**`, `$$`, `{#eq:x}`, `[@key]`, `%%note%%`, front matter keys).
- Code: macros, Python and JavaScript samples, LaTeX commands, regular expressions, CSS class names, HTML tags.
- Settings keys, command ids (`format.bold`), event names, IPC channels, file extensions, MIME types, language codes, URLs.
- Key names inside shortcuts as stored (`Ctrl+Shift+K`); the shell formats them for display.
- Product and format names: Markooj, Pandoc, PDF, DOCX, EPUB, LaTeX, BibTeX, KaTeX, Mermaid, Python, GitHub, Word, Excel.
- Messages for developers: `console.*`, thrown errors that never reach a person, test names and assertion text.
- Data: document titles, file names and paths, user dictionaries, macro names, language names in their own script.

## Pseudo-locale

The test language `qps` turns every string that goes through `app.t` into accented, about 35 % longer text in brackets:
`Save as…` → `[Šåṽé åš… ~~~]`. Anything still plain English on screen skipped `app.t`. It also shows where longer
translations will not fit.

- Turn it on: command search (Alt+Q) → "Show the test language in the language list", then pick **Pšéûðö** from the
  status-bar language menu. Or start with `MARKOOJ_UI_LANGUAGE=qps npx electron .`.
- The smoke test `i18n: pseudo-locale coverage scan` switches to `qps`, opens every ribbon tab, File → Options, the command
  search, the language menu and a dialog, and writes `<smoke folder>/i18n-untranslated.json`: every visible text and
  `title` / `aria-label` / `placeholder` / `data-tip` / `data-tip-d` that is not pseudo-translated, with where it was found.
  Document text and headings, file names, web addresses, language names and tags, brand names, format badges (`DOCX`),
  shortcut and key names, cross-reference labels (`eq:`) and numbers are allowed. The test fails above
  `app.i18n.scanThreshold`, which is 0: every visible interface string must go through `app.t`.
- Data that is shown in the interface but must not be translated (document headings in the outline, macro names, credits and
  license names, thesaurus words, cross-reference previews, help page titles) carries `translate="no"`, so the scan skips it.

```
npx electron . --smoke smoke-i18n --smoke-only "^i18n:"
```

## The check script

```
node scripts/i18n-check.js                  every language
node scripts/i18n-check.js --lang ur        one language, with the full list of missing strings
node scripts/i18n-check.js --scan           also compare the code with locales/en
node scripts/i18n-check.js --write          store each language's completeness in locales/languages.json
```

It reports per language: missing strings, extra strings (no longer in English), strings in another group, empty values,
placeholder mismatches, HTML tag mismatches, plural gaps (per `Intl.PluralRules` of the language), values identical to English
(unless allowed with `@same`), translations more than twice as long as a short English label, and the completeness
percentage. `--scan` lists text used in the code but missing from `locales/en`, English strings no longer used, and calls whose
text is built at run time (check those by hand).

**Errors** (exit code 1): invalid JSON, a lost or invented placeholder, different HTML tags, a missing `other` plural form,
plural forms on text without a count (or one string for a count in a language with several forms), a bad context marker, an
English value that differs from its key. **Warnings** never fail the run. `--strict` also fails on plural gaps, strings missing
from `locales/en` and unused English strings (for the final release check). Options: `--verbose`, `--max N`, `--json`.

## Adding a language

1. Add a line to `locales/languages.json`: `code` (BCP 47), `name` (in English), `native`, `dir`, `intl`, `plural`, `font`.
2. Create `locales/<code>/` with one `{}` file per group (copy the file names from `locales/en/`) and a `GLOSSARY.md`.
3. If the language is written right to left, the interface mirrors by itself (`<html dir="rtl">`); check the screenshots.
4. If it needs its own interface font, add a `.mk-ui-font-<font>` rule to `src/i18n.css`.
5. Add the code to `UI_LANGUAGES` in `main-features.js`, the installer's language page (`build/installer.nsh`) and
   `electronLanguages` in `package.json` (Chromium's own messages).
6. Translate, run `node scripts/i18n-check.js --lang <code>`, then the smoke test.

## For translators and reviewers

1. **Glossary first.** Fill `locales/<code>/GLOSSARY.md`: the style (how to address the user, punctuation, digits) and one
   agreed word for each term. Every file then uses the same words.
2. **Translate meaning, not words.** Write what a careful native speaker would put in Microsoft Word's menus in your language.
   Keep labels short. Messages start with what the person can do, then what still works (the English does this too).
3. **Keep** placeholders `{name}`, tags such as `<kbd>`, product names, and keyboard keys exactly as they are.
4. **Plural text** gets every category your language uses.
5. **Check** with `node scripts/i18n-check.js --lang <code>` until it shows no errors, then look at the screens (the smoke
   screenshots, or switch the language from the status bar).

**Native speakers: please review.** If a word is wrong, stiff or machine-like, tell us through the
[contact form](https://tally.so/r/db9jlN?from=i18n-doc) or open an issue on
[GitHub](https://github.com/datakeen/markooj/issues) with the language, the screen and your better wording. Inside Markooj,
File → Options → Language has a "Suggest a better translation" link.
